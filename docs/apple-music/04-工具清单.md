# 04 · 工具清单

> 一句话摘要：按「开发 → 联调 → 构建 → 发布」四个阶段列出本项目实际用到的每个工具，写清它解决什么问题、是否必需、以及不用它还能怎么办。

---

## 1. 开发与类型检查

| 工具 | 解决什么问题 | 必需？ | 替代品 / 不用会怎样 |
| --- | --- | --- | --- |
| **Node.js**（`24.22.0`，npm `11.19.1` 实测通过） | 运行 Vite、Electron 主进程脚本、测试 | 必需 | 无。版本不对时 `electron-builder` 与原生依赖最易出问题 |
| **npm** | 依赖安装与脚本入口 | 必需 | pnpm/yarn 理论可用，但上游脚本与 lockfile 为 npm，换包管理器要自己验证 |
| **TypeScript**（`tsc --noEmit`） | 改上游类型契约（Provider、播放标识）后立刻发现类型漂移 | 强烈建议 | 没有它，跨 40+ 文件的类型改动只能靠运行时试错 |
| **ESLint**（上游配置） | 保持与上游代码风格一致，降低合并冲突 | 建议 | 不跑也能提交，但后续同步上游时噪声大 |
| **Prettier**（上游配置） | 同上 | 建议 | 同上 |

---

## 2. 联调与验证

| 工具 | 解决什么问题 | 必需？ | 替代品 / 不用会怎样 |
| --- | --- | --- | --- |
| **Vitest** | 单测：归一化、Provider 契约、队列映射、supervisor 行为 | 必需 | 无。这些逻辑无法靠手点验证 |
| **Playwright**（上游自带） | 上游的 UI 快照/组件测试 | 可选 | 本项目未新增 UI 快照测试；不做也能发布 |
| **Chrome DevTools Protocol（CDP）** | 指挥 Apple Music 网页实例：建队列、播放、读状态、读歌词 | **本项目核心** | 没有等价公开接口可用（Apple 未提供供第三方操控网页播放器的 API）。替代思路见下 |
| **`ws`（WebSocket 客户端）** | CDP 需要 WebSocket 长连接；本项目自带 62 行零依赖客户端 `cdp-lib.mjs`，只依赖 `ws` 这一件事 | 必需（已在 `dependencies`，`^8.21.3`） | 可用 Node 内置 `WebSocket`（Node ≥ 21 起提供，`24.22.0` 实测可用）。不引入 `ws` 也可以，但要改写握手与分帧 |
| **Microsoft Edge / Chrome（Chromium 内核）** | 承载 Apple Music 网页并真正出声 | 必需 | 必须是 Chromium 内核浏览器；Firefox 不支持本项目使用的 CDP 子集 |
| **`<任意浏览器>` 开发者工具 → Network** | 观察 Apple 网页自身的请求形状（路径、查询参数、响应字段） | 联调期必需 | 无替代：这是唯一能确认「字段到底叫什么」的手段 |
| **`netstat -ano`（或资源监视器）** | 确认 `9863`/调试端口归属、排查端口被占 | 建议 | 换 `Get-NetTCPConnection`（PowerShell）同理 |
| **临时探针脚本（Node）** | 直接调用 CDP 校验「某条命令是否真的生效」，避免改前端界面来试 | 强烈建议 | 只用界面验证会把「桥的问题」和「界面的问题」混在一起，排障成本翻倍 |

## 3. 构建与打包

| 工具 | 解决什么问题 | 必需？ | 替代品 / 不用会怎样 |
| --- | --- | --- | --- |
| **Vite**（上游自带） | 构建渲染进程产物 | 必需 | 无（上游工程结构绑定 Vite） |
| **electron-builder** | 生成 `win-unpacked` 与安装包、写 asar、裁剪依赖 | 必需 | electron-forge 需要重写整套配置；不推荐 |
| **离线构建参数** `-c.electronDist=…` + `-c.win.signAndEditExecutable=false` | 在无法访问外网（下载代码签名工具失败）时仍能出包 | 视网络环境 | 网络通畅时不需要；国内环境通常需要 |
| **镜像前缀**（`ELECTRON_BUILDER_BINARIES_MIRROR=<镜像地址>`） | 替代直连下载 electron/签名工具 | 视网络环境 | 直连可用就不需要；注意镜像可能缺文件或很慢 |
| **`gh-proxy` 类加速前缀** | 拉取 GitHub 上的构建资产 | 视网络环境 | 有代理/VPN 时不需要 |
| **7-Zip / tar（Git Bash 自带）** | 备份源码快照、检查产物内容 | 建议 | 用 `git archive` 也能做快照 |
| **资源编辑器（`resedit`，纯 JS）** | 改可执行文件图标/版本信息而不破坏 PE 结构 | 可选 | 不做也不影响功能；`rcedit 0.2.0` 对现代 Electron 产物实测失败，见 03 |
| **PowerShell + `System.Drawing`** | 生成多尺寸 ICO | 可选 | 用 ImageMagick `convert`，或现成 ICO 文件 |

## 4. 发布与仓库维护

| 工具 | 解决什么问题 | 必需？ | 替代品 / 不用会怎样 |
| --- | --- | --- | --- |
| **Git** | 分支/标签/上游同步、生成「哪些文件是我改的」 | 必需 | 无 |
| **GitHub Releases** | 分发二进制 + 附源码入口（AGPL 义务） | 必需 | 自建站点也可以，但必须同时提供源码 |
| **`git archive` / 源码包** | 保证 Release 附件里的源码与二进制完全对应 | 强烈建议 | 只给标签链接也行（GitHub 会自动生成 tag 的源码包） |
| **`git fsck` + `git status`** | 发布前确认仓库完整、工作区干净 | 建议 | 无替代，是最后一道自检 |
| **密钥扫描（`gitleaks` / `trufflehog` / 自查脚本）** | 确认提交历史里没有真实密钥 | 必需 | 手工 `grep` 只能覆盖当前文件，覆盖不了历史，不推荐 |

---

## 5. 明确「没用到」的工具（避免误以为需要）

| 工具 | 为什么没用 |
| --- | --- |
| **Frida / 逆向调试器** | 本项目不分析 Apple 客户端，只操作网页 |
| **抓包代理（mitmproxy/Charles）+ 证书安装** | 不需要解密流量：数据要么走浏览器页面内请求，要么由 CDP 读取。安装根证书反而增加风险 |
| **Apple 私有 API / MusicKit JS 私有接口** | 只使用网页端在正常使用中会发起的公开请求 |
| **模拟点击（坐标/图像识别）** | 用 CDP 直接调用页面内 API，比模拟点击稳定得多 |
| **本地音频解码/DRM 处理** | 受 DRM 保护，且明确不在本项目范围内 |
