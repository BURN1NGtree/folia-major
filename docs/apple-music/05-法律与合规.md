# 05 · 法律与合规

> 一句话摘要：本项目是 AGPL-3.0 衍生作品，**义务是「开源、保留声明、标注修改、给源码」四条**；同时它只驱动用户自己的 Apple Music 会话，不涉及解密或内容抓取——这两件事要在文档里说清楚，而不是模糊带过。

---

## 1. 许可证事实

| 项 | 值 | 依据 |
| --- | --- | --- |
| 上游许可证 | GNU Affero General Public License, Version 3 | 上游仓库根目录 `LICENSE` |
| 上游声明 | `package.json` 的 `"license": "AGPL-3.0"`；README 亦声明 AGPL-3.0 | 文件实读 |
| 本项目许可证 | **必须**沿用 AGPL-3.0 | AGPL 第 5 条：衍生作品整体须按同一许可证分发 |

> 结论：**不存在「换个许可证发出去」的选项**。AGPL 是强传染性（copyleft）许可证，你的修改版必须继续以 AGPL-3.0 发布。

---

## 2. AGPL-3.0 给衍生分发者的六条硬义务

| # | 义务 | 在本项目中怎么落实 |
| --- | --- | --- |
| 1 | 整包以 AGPL-3.0 分发 | 仓库根保留上游 `LICENSE` 原文；README/Releases 声明许可证 |
| 2 | 保留版权声明与许可声明 | 不删除任何源文件头部的版权注释；`LICENSE` 不改写、不替换 |
| 3 | 显著标注修改 | Git 历史 + `CHANGELOG.md` + README 的「基于上游修改」声明；发布说明写清「本版修改了什么」 |
| 4 | 提供对应源码（Corresponding Source） | 每个 Release 必须能让人拿到**构建该二进制所用的源码**：给标签链接即可（GitHub 会生成源码包） |
| 5 | 网络服务条款（第 13 条） | 本地桌面应用不触发；若将来做云端/远程版本，须向使用者提供源码获取方式 |
| 6 | 不得追加更严限制 | 不得加「禁止商用」「禁止二次分发」等条款；也不得用 EULA 覆盖 AGPL 权利 |

**「对应源码」包含什么**：构建脚本、打包配置、依赖锁定文件（`package-lock.json`）、以及为生成二进制而修改/新增的所有源码。缺一样都算不完整。

## 3. `NOTICE` 怎么写

AGPL 不强制要求 `NOTICE` 文件（那是 Apache-2.0 的机制），但**强烈建议**加一份，作用是把「基于谁、改了什么、谁负责」写死，避免被误认原创。

```text
本项目（本仓库及其发布产物）
  名称：      <本项目名称>
  版本：      v0.7.20-apple.1
  性质：      基于上游项目的二次开发 / 衍生版本（modified version）
  作者：      <本项目作者>

上游项目
  名称：      <上游项目名>
  仓库：      <上游仓库地址>
  许可证：    GNU Affero General Public License v3.0
  版权：      归上游作者与贡献者所有
  本项目基于的提交：<上游提交号>

修改声明
  本仓库包含对上游源码的修改与新增文件，修改内容见 CHANGELOG.md 与 Git 历史。
  本项目的改动同样以 AGPL-3.0 授权。

免责
  本项目非官方，与上游官方团队无关；与 Apple Inc. 无关联，未获其认可或背书。
  本项目按「现状」提供，不附带任何担保。

商标
  Apple、Apple Music 等为 Apple Inc. 的商标，仅用于说明兼容/接入对象。
  <上游项目名> 为其权利人的名称/商标。
```

## 4. 第三方依赖与资产

| 类别 | 处理方式 |
| --- | --- |
| 上游已引入的依赖 | 沿用上游的选择与许可证，不额外处理；但**发布前**可用 `npx license-checker --summary` 出一份清单备查 |
| 本项目新增依赖（如 `ws`） | 确认其许可证（`ws` 为 MIT）与 AGPL 兼容；在文档中记录版本 |
| 字体 / 图标 / 音效 | 只使用仓库内已有或明确开源授权的资源；**不要**从 Apple 官网抓取图标/截图作为素材 |
| 示例数据（歌单、曲目 JSON） | 用脱敏、手写的最小样本，不用真实抓取结果 |

## 5. 与 Apple 相关的合规边界（重要）

本项目**做到什么**：

- 在用户自己的浏览器里，打开 Apple Music 网页版；
- 用浏览器自动化协议（CDP）指挥该网页**执行用户本来也会手动做的操作**（搜索、建队列、播放、切歌、读播放位置）；
- 展示方向是把 Apple 返回的公开页面数据映射到上游的界面结构。

本项目**不做**：

- 不解密受 DRM 保护的音频，不下载、不转码、不留存音频；
- 不绕过登录、验证码、二次验证等任何访问控制；
- 不批量抓取受版权保护的内容，不提供内容镜像/分发；
- 不伪造请求头冒充 Apple 官方客户端。

**使用者需自行确认**：自动化操作自己的 Apple 账号是否符合 Apple 的服务条款与所在地区法律。文档与代码中均不提供任何规避手段。

> 建议在 README 的显著位置放一段「合规提示」，措辞见 `02-README.md` 的 FAQ「会不会违反 Apple 服务条款？」。

## 6. 发布前必须核对的法律项

- [ ] 仓库根 `LICENSE` 为上游原文（未被替换、未被追加条款）
- [ ] `package.json` 的 `license` 字段仍为 `AGPL-3.0`
- [ ] README 顶部有「基于上游修改 + 致谢 + 非官方 + 与 Apple 无关联」
- [ ] Release Notes 写明「本版修改内容」
- [ ] Release 页面能到达对应源码（标签链接或源码包）
- [ ] `NOTICE` 已更新本项目版本号与上游基底提交
- [ ] 未在仓库任何位置（含历史）出现真实密钥、Cookie、账号、真实路径与内网地址
- [ ] 未使用他人商标作为本项目名称（含「官方」「正版」等误导性表述）
- [ ] 截图/文档素材无 Apple 官方素材的未授权使用
